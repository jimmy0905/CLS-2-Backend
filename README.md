# CLSense-Backend

## Database Migrations

The backend uses Alembic to keep the PostgreSQL schema in sync with the SQLAlchemy
models.

By default, app startup runs pending migrations, autogenerates an additive
migration if the current models differ from the database, and applies it
immediately. Autogenerated drop, alter, or raw SQL operations are blocked so they
can be reviewed manually. Configure this with:

```env
DATABASE_AUTO_MIGRATE=true
DATABASE_AUTO_GENERATE_MIGRATIONS=true
DATABASE_BOOTSTRAP_SCHEMA=false
```

`DATABASE_BOOTSTRAP_SCHEMA=true` enables the legacy SQLAlchemy `create_all()`
bootstrap path for local empty databases. Keep it disabled when you want schema
changes controlled only by Alembic migrations.

Fresh databases do not create a default admin unless explicitly enabled:

```env
BOOTSTRAP_DEFAULT_ADMIN=false
BOOTSTRAP_DEFAULT_ADMIN_USERNAME=admin
BOOTSTRAP_DEFAULT_ADMIN_PASSWORD=
```

For manual migration control, disable autogeneration and create revisions from the
backend directory:

```bash
cd backend
alembic revision --autogenerate -m "describe schema change"
alembic upgrade head
```
